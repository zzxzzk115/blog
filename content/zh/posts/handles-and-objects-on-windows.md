对于 Windows 里的 Handles(句柄) 和 Objects(对象) 两个概念，我们应该如何理解？

<!--more-->

# Handles and Objects 句柄和对象

Windows 里的 **对象是一种数据结构，它表示系统资源，例如一个文件、一个线程、一张图片等等...** 

但是，应用程序不能直接访问对象的数据或对象表示的系统资源。相反，应用程序必须获得一个对象 **句柄** ，它可用于检查和修改系统资源。

每个句柄在一个内部维护表中都有一个条目，这些条目包含资源的地址和标识资源类型的方法。

## 为什么 Windows 要有这两个概念

系统使用对象和句柄来调节对系统资源的访问，主要有两个原因。首先，对象的使用确保了 Microsoft 可以更新系统功能，只要原始对象接口得到维护。当系统的后续版本发布时，我们可以使用更新后的对象，而不需要进行额外的工作。

其次，对象的使用使我们能够利用 Windows 的安全性。每个对象都有自己的访问控制列表(ACL) ，该列表指定进程可以对该对象执行的操作。每当应用程序创建对象的句柄时，系统都会检查对象的 ACL。

## Object Manager 对象管理器

对象由标准头和对象特定的属性组成。因为所有对象都具有相同的结构，所以 Windows 中只有一个对象管理器来维护所有对象。

对象头部包括对象名称之类的条目，以便其他进程可以按名称引用对象，以及安全描述符，以便对象管理器可以控制哪个进程访问系统资源。

对象管理器执行的任务包括:

- 创建对象
- 验证进程是否有权使用对象
- 创建对象句柄并将其返回给调用方
- 维护资源配额
- 创建重复的句柄
- 关闭对象的句柄

## Object Interface 对象接口

Windows 提供了执行以下任务的函数:

- 创建一个对象
- 获取一个对象句柄
- 获取关于对象的信息
- 设置关于对象的信息
- 关闭对象句柄
- 摧毁对象

对于每个对象来说，其中一些任务是不必要的。其中一些任务是为某些对象而组合的。例如，应用程序可以创建事件对象。其他应用程序可以打开该事件以获得该事件对象的唯一句柄。当每个应用程序结束使用事件时，它将关闭对象的句柄。当事件对象没有剩余的打开句柄时，系统将销毁事件对象。相反，应用程序可以获得现有窗口对象的句柄。当不再需要窗口对象时，应用程序必须销毁该对象，这将使窗口句柄失效。

有时候，在关闭所有对象句柄之后，对象仍然保留在内存中。例如，线程可以创建事件对象并等待事件句柄。当线程在等待时，另一个线程可以关闭相同的事件对象句柄。事件对象保留在内存中，没有任何事件对象句柄，直到将事件对象设置为有信号状态并完成等待操作。此时，系统从内存中删除对象。

句柄和对象会消耗内存。因此，为了保持系统性能，您应该在不再需要句柄时立即关闭它们并销毁它们。如果不这样做，由于过度使用分页文件，应用程序可能会损害系统性能。

当进程终止时，系统自动关闭句柄并删除进程创建的对象。但是，当线程终止时，系统通常不会关闭句柄或删除对象。唯一的异常是窗口、钩子、窗口位置和动态数据交换(DDE) 会话对象; 当创建线程终止时，这些对象将被销毁。

## Handle Limitations 句柄限制

有些对象一次只支持一个句柄。系统在应用程序创建对象时提供句柄，并在应用程序销毁对象时使句柄失效。其他对象支持对单个对象的多个句柄。在关闭对象的最后一个句柄之后，操作系统会自动从内存中删除对象。

系统中打开句柄的总数仅受可用内存量的限制。有些对象类型支持每个会话或每个进程有限数量的句柄。

## Handle Inheritance 句柄继承

子进程可以继承其父进程的句柄。继承的句柄仅在子进程的上下文中有效。若要使子进程能够从其父进程继承打开的句柄，需要使用以下步骤:

1. 创建 **bInheritHandle** 属性设置为 TRUE 的句柄.
2. 用 **CreateProcess** 方法，**bInheritHandle** 参数设置为 TRUE，创建子进程.

Dupicatehandle 函数复制要在当前进程或其他进程中使用的句柄。如果应用程序重复其用于另一个进程的句柄之一，则重复的句柄仅在其他进程的上下文中有效。

复制或继承的句柄是唯一的值，但它引用的对象与原始句柄相同。进程可以继承或重复下列类型的对象的句柄:

- Access Token 访问令牌
- Communications device 通讯设备
- Console input 控制台输入
- Console screen buffer 控制台屏幕缓冲区
- Desktop 桌面
- Directory 目录
- Event 事件
- File 文件
- File mapping 文件映射
- Job 任务
- Mailslot 邮槽
- Mutex 互斥器
- Pipe 管道
- Process 进程
- Registry key 注册表项
- Semaphore 信号量
- Socket 套接字
- Thread 线程
- Timer 计时器
- Window station 窗口站

所有其他对象对于创建它们的进程都是私有的; 它们的对象句柄不能被复制或继承。

## Object Categories 对象类别

对象分为：

- User Objects 用户对象
- GDI Objects 图形设备接口对象，GDI 对象
- Kernel Objects 内核对象

用户对象支持窗口管理，GDI 对象支持图形处理，内核对象支持内存管理、进程执行和进程间通信(IPC)。

### User Objects 用户对象

用户对象只支持每个对象拥有一个句柄。进程不能继承或重复用户对象的句柄。一个会话中的进程不能引用另一个会话中的用户句柄。

每个会话的理论上限为 65,536 个用户句柄。但是，每个会话可以打开的用户句柄的最大数量通常较小，因为它受到可用内存的影响。还有一个默认的每个进程用户句柄限制。若要更改此限制，需要设置以下注册表值:

`HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows\USERProcessHandleQuota`

这个值可以设置为一个介于 200 到 18,000 之间的数字。

#### Handles to User Objects 用户对象句柄

用户对象的句柄对所有进程都是 public (公共) 的。也就是说，任何进程都可以使用用户对象句柄，只要该进程具有对对象的安全访问权限。

### GDI Objects 图形设备接口(GDI) 对象

GDI 对象只支持每个对象拥有一个句柄。GDI 对象的句柄对进程是 private (私有) 的。也就是说，只有创建 GDI 对象的进程才能使用 GDI 对象句柄。

每个会话理论上限为 65,536 个 GDI 句柄。但是，每个会话可以打开的 GDI 句柄的最大数量通常较小，因为它受可用内存的影响。

GDI 句柄也有默认的每个进程限制。要更改此限制，需要设置以下注册表值:

`HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows\GDIProcessHandleQuota`

这个值可以设置为一个介于 256 和 65,536 之间的数字。

### Kernel Objects 内核对象

内核对象句柄是特定于进程的。也就是说，进程必须创建对象或打开现有对象以获取内核对象句柄。内核句柄的每个进程个数上限是 2 的 24 次方。但是，句柄存储在分页池中，因此可以根据可用内存创建的实际句柄数量。可以在 32 位 Windows 上创建的句柄数明显低于 2 的 24 次方。

任何进程都可以创建现有内核对象的新句柄(即使是由另一个进程创建的内核对象) ，前提是该进程知道对象的名称并具有对对象的安全访问权限。内核对象句柄包括访问权限，这些权限指示可以授予或拒绝进程的操作。应用程序在创建对象或获取现有对象句柄时指定访问权限。每种类型的内核对象都支持自己的访问权限集。例如，事件句柄可以设置或等待访问权限(或者两者都有) ，文件句柄可以具有读或写访问权限(或者两者都有) ，等等。
